How the agent resolves a Slack user to tasks across all bases

Update task
Owning base: tasks or acq_tasks
Agent patches due_date or status on the
specific record in the owning base. Never

Key design rules
1. employees.slack_id and employees.airtable_user_id are UNIQUE constraints — the agent can rely on a single-row
result from the identity lookup.
2. The agent NEVER writes to synced ([SYNC]) tables. All writes go to the table's owning base.
3. tasks.airtable_user_id and acq_tasks.airtable_user_id are denormalised copies of the user ID — no join needed at
query time, enabling fast filtering.
4. When an employee is marked employment_status = 'inactive', the agent returns no results for them — no special
agent-side logic needed.
5. All task tables share the same due_date field name intentionally, so the agent can apply the same date filter across all
task sources.
